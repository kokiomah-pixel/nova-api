## Principle

Effective institutional operating models are discovered through bounded implementation, repeated use, explicit authority, and the learning produced when intelligent systems encounter real workflows.

For Sharpe Nova OS:

> Every bounded implementation must produce useful review context for the present action and institution-owned learning that can improve later review of the same action class without converting observed behavior into policy automatically.

## Dual-output requirement

```yaml
bounded_implementation_outputs:
  current_workflow_output:
    - useful_review_context
    - visible_source_state
    - applicable_constraint_context
    - unresolved_conditions
    - explicit_authority_handoff

  institutional_learning_output:
    - evidence_requirements_observed
    - constraints_applied_or_disputed
    - authority_roles_observed
    - exceptions_and_overrides
    - source_disagreements
    - chronology_relevance
    - proposed_refinements_for_review
```

## Evidence status

Observed practice must remain distinguishable from formally adopted governance.

```yaml
operating_model_evidence_status:
  permitted_values:
    - formally_defined
    - observed_in_practice
    - accepted_by_authority
    - exception_only
    - disputed
    - proposed_for_review
    - formally_adopted
    - superseded
```

Observed behavior does not become policy, a constraint, accepted state, Reflex Memory, or implementation authority without explicit local acceptance.

## Design-partner qualification

A bounded implementation should prefer workflows with:

- a recurring consequential action;
- an identifiable start and end;
- a named workflow owner;
- a named local authority;
- measurable current friction;
- accessible evidence sources;
- observable external execution;
- possible outcome feedback; and
- willingness to refine the workflow.

## Services-to-product discipline

Services are justified only when they produce reusable Nova structure, including:

- a bounded workflow map;
- review ontology;
- evidence-source map;
- source-authority rules;
- constraint-applicability map;
- authority map;
- external-system map;
- chronology-retention rules;
- success and learning metrics; and
- a reusable workflow template.

## Non-authorizations

This principle does not authorize:

- automatic workflow redesign;
- automatic policy updates;
- automatic Reflex Memory mutation;
- organization-wide transformation scope;
- generic AI-management positioning;
- runtime engineering; or
- production deployment.
