# Governance-Context Rot

## Status

Governance concept note  
Reviewer-facing explanation  
Non-authority documentation layer

## Purpose

This note defines governance-context rot as a decision-context degradation risk in agentic and programmable capital environments.

Governance-context rot occurs when review context becomes too large, fragmented, stale, source-conflicted, or unstructured before local authority is asked to decide.

Sharpe Nova OS exists before that decision point.

Nova does not create a larger context window.

Nova structures governed review context before local authority acts.

---

## Canonical Boundary

Agent prepares action.  
Nova structures review context.  
Local authority decides.  
Nova does not execute.

This boundary governs every interpretation of governance-context rot.

Nova does not approve, deny, authorize, block, route, settle, execute, process payments, move capital, control agents, manage wallets, perform compliance review, perform audit reporting, or replace local authority.

---

## Definition

Governance-context rot is the degradation of review coherence when decision context becomes too large, fragmented, stale, source-conflicted, or unstructured before authority is asked to decide.

It is not the same as missing information.

It is the condition where information exists, but the review environment can no longer preserve enough coherence for disciplined pre-action review.

---

## Why This Matters

Agentic financial workflows can prepare actions faster than institutions can assemble governed review context.

A prepared capital action may involve:

- agent intent
- custody account state
- custody state
- settlement assumptions
- stablecoin liquidity
- tokenized deposit constraints
- collateral eligibility
- jurisdictional context
- counterparty exposure
- policy constraints
- market conditions
- prior overrides
- prior non-actions
- chronology records
- local authority requirements

If this context is dumped into one unstructured review surface, the review process can lose coherence before capital moves.

The problem is not only whether an action is prepared.

The problem is whether the institution has governed context before local authority decides.

---

## Symptoms

Governance-context rot may appear when:

- reviewers miss relevant prior events
- operators over-weight the latest signal
- constraints are visible but not connected
- source systems disagree without reconciliation
- prior overrides are forgotten
- prior non-actions disappear from memory
- agent retries appear as fresh proposals
- custody and settlement dependencies are reviewed separately
- collateral, venue, and authority context are disconnected
- stale connector artifacts are treated as current truth
- source-incomplete runs are interpreted without limitation notes
- public framing drifts from review context into authority language

These symptoms weaken decision discipline before execution.

---

## Nova's Role

Nova's role is not to predict the outcome of a capital action.

Nova's role is not to approve or reject the action.

Nova's role is not to execute, route, settle, or process the action.

Nova's role is to structure governed pre-action review context before local authority acts.

This includes preserving or organizing context around:

- source segmentation
- chronology
- classification stability
- proof reproducibility
- authority-scope recognition
- non-authority telemetry
- constraint logic
- review-context completeness
- boundary-state clarity

Nova reduces governance-context rot by making the review environment more coherent before a decision is made by local authority.

---

## Not More Context - Better Governed Context

Governance-context rot is not solved by adding more information to the reviewer's surface.

More context can worsen review coherence if it is unstructured, stale, duplicated, or source-conflicted.

The goal is not maximum context.

The goal is governed context.

Correct framing:

```text
Not more context.
Better governed context.
```

Nova should help structure the right context into the right review posture before authority acts.

---

## Relationship to Chronology

Chronology is one of Nova's defenses against governance-context rot.

Chronology preserves decision-state lineage: what was known, what changed, what was corrected, what was accepted, what was paused, what sources were available, what sources were missing, and what boundary was active at the time.

Without chronology, every review risks starting from zero.

With chronology, future review can reference accepted decision-state lineage rather than reconstructing memory from scattered traces.

Chronology is not a knowledge base.

Chronology is decision-state memory for pre-action governance.

---

## Relationship to Source Segmentation

Source segmentation helps prevent context collapse.

When context comes from different systems, documents, operators, agents, or connectors, Nova should preserve the distinction between those sources.

This helps reviewers understand:

- what was source-confirmed
- what was Architect-provided
- what was CCO-reconciled
- what was unavailable
- what may be stale connector output
- what should not be treated as complete operating truth

Source segmentation protects review context from false certainty.

---

## Relationship to Classification Stability

Classification stability helps prevent review drift.

If similar inputs produce inconsistent review classifications without a meaningful source or context change, review discipline weakens.

Nova's proof and replay posture should support stable classification behavior where applicable.

Classification stability is not an investment outcome claim.

It is a governance credibility requirement.

---

## Relationship to Proof Reproducibility

Proof reproducibility helps reviewers reconstruct how a review context was formed.

A review packet matters only if it can be inspected, replayed, or reconstructed within the limits of the proof workflow.

Proof reproducibility does not prove production readiness, market validation, buyer validation, or adoption.

It supports reviewability.

---

## Relationship to Authority-Scope Recognition

Governance-context rot increases when authority boundaries become unclear.

Nova should preserve the distinction between:

- prepared action
- review context
- local authority decision
- execution outside Nova

Authority-scope recognition helps prevent the system from implying that Nova approves, denies, authorizes, blocks, routes, settles, executes, or controls capital movement.

---

## Capital-Action Context Domains

A prepared capital action may require review across multiple context domains.

Examples include:

- intent context
- asset context
- rail context
- custody context
- collateral context
- counterparty context
- jurisdiction context
- constraint context
- chronology context
- authority context
- source context
- counterfactual context

Nova should not ask one reviewer, one agent, one dashboard, or one model pass to hold the entire capital-action context unaided.

Nova's governance discipline should support structured review-context formation.

---

## Deterministic Coverage Principle

Governance coverage should be driven by schema and review discipline, not reviewer memory alone.

For execution-adjacent capital actions, required context fields should be considered consistently.

A reviewer may remember some required fields.

A generic agent may mention some required fields.

Nova's governance posture should help ensure that required review dimensions are surfaced before local authority acts.

This does not mean Nova decides.

It means Nova helps structure the context that makes local review possible.

---

## Safe Internal Architecture Language

When discussing future internal architecture, use boundary-safe language.

Preferred:

- review-context domains
- context composer
- authority-scope recognition
- classification posture
- source segmentation
- chronology retrieval
- counterfactual review context
- pre-action review packet
- local review preparation

Avoid or heavily qualify:

- authority cell determines review path
- posture composer decides
- classify and act
- route for review
- execution control
- approval flow
- agent supervisor
- automated acceptance
- automatic memory mutation

If a term could imply Nova controls action or authority, replace it with review-context language.
