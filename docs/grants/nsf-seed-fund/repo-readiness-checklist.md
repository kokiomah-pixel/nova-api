# Repository Readiness Checklist

Use this checklist before NSF Seed Fund review and before public partner review.

- [x] README explains Nova clearly
- [x] proof determinism described as infrastructure credibility
- [x] non-authority boundary visible
- [x] continuity docs visible
- [ ] test suite passing in current branch
- [ ] doctrine lint passing in current branch
- [x] no secrets intentionally committed
- [x] examples do not imply execution authority
- [x] no Arc/Circle-specific expansion unless protocol-neutral
- [x] license present
- [x] security policy present or planned
- [x] contributing guide present or planned
- [x] roadmap present or planned
- [x] CI present or planned

## Final Review Questions

- Does the repo clearly state what Nova is?
- Does the repo clearly state what Nova is not?
- Does the repo explain technical novelty without product overclaiming?
- Does the repo preserve research risk as unresolved R&D?
- Does the repo explain how Phase I would validate the system?
- Does the repo identify a credible commercialization pathway?
- Does the repo connect proof determinism to infrastructure credibility?
- Does the repo preserve the boundary that Nova conditions environments before execution without authorizing action?

Sharpe Nova OS is not asking NSF to fund a trading system.

It is asking NSF to fund research and validation of pre-execution environmental governance infrastructure for autonomous capital systems.
