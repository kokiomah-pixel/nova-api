## Purpose

This document explains why Sharpe Nova OS remains strictly non-authority and pre-execution, how that stance can become commercially valuable, and where it may create commercial pressure.

Nova's non-authority stance is a strategic boundary.

It is not a lack of seriousness.

It is not a claim that execution control is unimportant.

It is a decision to preserve institutional sovereignty while structuring governed review context before local authority acts.

## Core Thesis

Non-authority is not non-essential.

Nova does not control execution.

Nova controls review readiness.

Execution systems may control movement.

Local authority decides.

Nova structures the governed context local authority should see before deciding.

## Canonical Boundary

Agent prepares action.  
Nova structures review context.  
Local authority decides.  
Nova does not execute.

Execution happens elsewhere.

## Commercial Value of Non-Authority

Nova's commercial value does not come from approving, denying, blocking, routing, settling, signing, or executing capital movement.

Nova's value comes from making agent-prepared financial actions review-ready before local authority decides.

Commercially, Nova can matter because institutions may need:

- governed context before local review
- source-state visibility before decision
- chronology-aware review posture
- Reflex Memory surfaced without autonomous authority
- review completeness standards
- proof metadata and reconstructability
- institution-owned governance chronology
- consistent review context across agents, rails, wallets, custodians, and workflows

Safe commercial compression:

```text
No governed review context, no local decision.
```

Unsafe commercial compression:

```text
No Nova, no execution.
```

The first preserves local authority.

The second incorrectly makes Nova sound like an execution gate.

## Why Non-Authority Can Lower Adoption Friction

Nova's non-authority stance may lower adoption friction because Nova does not require institutions to replace or surrender control over:

* execution systems
* custodians
* wallets
* payment rails
* treasury management systems
* ERP systems
* portfolio systems
* compliance systems
* audit systems
* local approval processes

Nova can sit before those systems as review-context infrastructure.

This reduces the need for Nova to become the system of record for execution or settlement.

## Why Non-Authority Can Become a Commercial Constraint

Non-authority can become a constraint if Nova is perceived as:

* optional documentation
* advisory commentary
* a dashboard
* passive reporting
* a compliance note
* a post-facto explanation layer
* a tool that does not affect operating behavior

This is the main commercial risk.

Nova must not be positioned as optional insight.

Nova should be positioned as required review-context infrastructure before local authority acts.

## Moat Logic

Nova's potential moat is not control over execution.

Nova's potential moat is durable ownership of the governed review-context standard and institution-owned governance chronology.

```yaml
moat_logic:
  agents_change: true
  rails_change: true
  wallets_change: true
  custodians_change: true
  execution_controls_change: true
  institution_governance_chronology_should_persist: true
```

Execution surfaces may change.

The institution's governance chronology should persist across them.

That is where Nova can become durable.

## When Buyers Ask for Blocking

Some institutions may eventually ask:

```text
Can Nova block the action?
```

The correct answer is layered.

Nova core does not block.

An institution may choose to require governed review context inside its own local policy, workflow, or execution-control layer.

Nova's role remains to emit governed review context.

```yaml
blocking_request_response:
  nova_core:
    role: structures_governed_review_context
    authority: none

  local_policy_system:
    role: decides_whether_missing_context_prevents_internal_review
    authority: institution_owned

  execution_system:
    role: executes_or_does_not_execute_based_on_local_authority_or_local_policy
    authority: outside_nova
```

Safe language:

```text
Institutions may require governed review context before local authority decides.
```

Unsafe language:

```text
Nova blocks actions that lack governed review context.
```

## Required Review Context vs Execution Control

Nova can be required without becoming an execution controller.

An institution may decide:

```text
No governed review context, no local decision.
```

That does not mean Nova executes.

That does not mean Nova authorizes.

That does not mean Nova blocks.

It means local authority has established a review discipline requiring governed context before decision.

## Comparison to Active Control Planes

Active governance or control-plane systems may operate closer to execution.

They may enforce policies, block actions, route transactions, supervise agents, or control runtime behavior.

Nova intentionally occupies a different layer.

```yaml
active_control_plane:
  position: near_or_inside_execution_runtime
  value: enforcement_or_control
  commercial_strength: visible_prevention_and_direct_policy_action
  risk: higher_authority_surface_and_integration_burden

sharpe_nova_os:
  position: before_local_authority_decides
  value: governed_review_context_and_chronology
  commercial_strength: sovereignty_portability_and_boundary_clarity
  risk: must_prove_review_context_is_required_not_optional
```

Nova should not compete by pretending to be an active control plane.

Nova should compete by owning the pre-action review-context layer.

## Strategic Tradeoff

Nova trades direct enforcement for:

* institutional sovereignty
* lower authority surface
* cross-agent portability
* cross-rail portability
* chronology durability
* review-context standardization
* clearer non-execution boundary

Nova gives up:

* direct blocking claims
* execution control claims
* immediate enforcement optics
* simple "we stop bad actions" marketing

This tradeoff is acceptable only if Nova becomes required review-context infrastructure.
